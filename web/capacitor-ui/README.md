# SillyClient UI

Android、Windows 和 GitHub Pages 共用同一套 React 控制台。本目录是主仓库维护的未适配基线前端源码。

```bash
pnpm install --frozen-lockfile
pnpm run dev
pnpm run typecheck
pnpm run build
```

`pnpm run build` 只生成 `dist/`。Android 使用 Android 仓库的 `scripts/sync-frontend.mjs` 同步，Windows 使用 `Sync-Frontend.ps1`，Pages 使用本仓库 `scripts/sync-pages-app.mjs`，不直接修改生成副本。

平台能力通过 `src/capacitor-plugin.ts` 中的 `TarvenEnv` 契约调用。浏览器预览使用 shim；新增或修改方法时必须同时更新 Kotlin 与 Electron 实现。

入口：APP 设置 → 通用 →「重新演示引导」。原有首次引导与完成标记保持不变，不因更换教程强制让老用户重看；网页演示仍由用户手动打开。

教程按认识启动器、创建与连接、卡片与运行、实例管理、终端与排错、背景与外观、应用设置、备份与迁移分为 8 章。网页演示包含 39 页，Windows 显示 38 页，Android / iOS 各显示 37 页；专属功能带平台说明，网页图示不等于原生能力已经执行或验收。

沿用原来的单面板分页与「上一步 / 下一步 / 完成」交互。桌面文字置左、对应截图置右，先读标题与短说明，再看图；窄屏改为文字在前、截图在后。章内小标签、底部章节圆点和总体阅读进度保留。前后按钮和左右方向键会经过全部章内页面，不跳章漏页；切页保留原来的方向轻移、失焦与淡入淡出。点击图片查看原图，Esc 返回，Tab 焦点留在当前弹层，退出后恢复底页交互与滚动。

`src/components/onboarding/guide-content.ts` 集中维护章节、平台范围、简短说明、必要提醒与图片尺寸。每页只保留一段短文，平均 34 字、最长 43 字；删除冗长的三步讲解与对应字段和样式，不在后台保留两套文案。用户已否决目录和搜索式手册布局，不要恢复；桌面单页左右分栏不改变原分页交互。

25 张当前真实界面截图位于 `public/onboarding/v4/`，使用示例实例与默认酒馆插图，总计约 287 KiB，不包含用户密码或私密聊天；13 张旧图已替换。组件与样式按需分包，只预取相邻图片，不为普通首页加载教程资源。切页按真实 CSS 过渡收尾，不依赖旧固定计时器或 JS 测量锁高；短屏正文可滚动，页脚保持可操作，不显示挤压布局的滚动条。

内容明确区分实例列表 JSON 与完整实例文件、隐藏控制台与取消任务、关闭远程连接与停止远端服务、默认目录偏好与迁移已有实例。查看教程不发起安装、命令、迁移、清理或删除操作。

保留启动时自动检查、设置维护页的手动检查与版本下载入口；不再维护应用内“版本主要更新”公告、自动弹出或重新查看入口。首次引导和 Windows 旧版实例迁移独立于公告，不依赖公告状态或已读版本记录。

## 实例管理面板

分类切换沿用全局 `motion-panel-face` 同位淡入、轻柔失焦与微小上浮；内容区和随内容变化的面板高度使用相同的溶解时长与缓动，避免内容与外框不同步。隐藏分类继续隔离指针和键盘焦点；减少动态效果时保留快速淡入，不做位移或模糊。

管理面板外壳继续使用共用的大毛玻璃材质；内部分区、字段和操作只用同色系的浅凹填色，不叠醒目的白底、亮边或高反差操作块。桌面高度随当前分类与实际表单展开自然调整，变化平滑；窄屏在视口范围内增长并保留内部滚动，实例带高度随屏幕留白伸缩。用户拖拽缩放后尊重手动尺寸，窗口跨桌面/窄屏时不丢失；关闭后重新打开恢复内容适配尺寸。四个分类保持相同宽度，避免横向跳动。管理页终端不自建颜色和字体，仍复用 `TerminalWell` 与共享终端令牌。

## 实例卡片信息层级

停止态与管理页版本标记保留第一次梯度弥散时的位置与几何：`rounded-md`、10px、500字重，白天使用3.5%黑色衬底与60%墨色，深色使用7%白色衬底与70%白字。运行态版本并入标题栏，使用无衬底、无边框的10px次级文字；不再另占一行或套胶囊。各处继续用 `formatDisplayVersion` 格式化，长版本省略并保留完整提示，不恢复已撤回的 `InstanceVersion` 组件或新增背景取样。

运行态默认只显示紧凑标题栏与终端，点击卡片或标题后才展开底部操作，再次点击收起；与停止态共用同一展开状态，同一时间只展开一张卡片。顶部仅同排名称与版本，不放独立按钮，也不恢复终端外重复的本地地址、运行提示和独立信息区。名称保持13px、400字重及80%墨色/白字，行高保持16px；版本保持无衬底10px、400字重，沿行盒中线而非不同字号的文字基线对齐，避免视觉下坠，仍作为次级信息而非第二个标题。标题栏另留12px横向内缩，名称左缘和版本右缘对齐终端内容而非圆角外框；两端文字距卡边各24px，避开外壳圆角。顶部内缩8px、标题行下另留3px，比上一轮将整行下移1px，修正用户实际截图中上方留白少于下方的偏上感；标题区19px，区域间距6px，顶部总厚度保持不变，终端左右仍内缩12px。视觉位置需结合用户实际缩放的截图校准，不能仅凭Canvas或像素中线近似就宣称视觉等距。240×320px卡片的终端距顶部仍为33px，默认高度277px，展开操作后为239px；日志与输入仍为11.5px、1.75行高，井内缩12px不变。

底部按「返回酒馆 / 关闭 / 更多」排列，保留32px点击高度；返回左对齐，关闭与更多以6px间距整体右对齐。两个文字按钮按内容自然宽度布局，统一10px横向padding，不拉伸分配剩余空间；保留返回宽、关闭窄的比例，更多仍为32px方形，窄屏不换行或挤压文字。普通详情与运行操作共用`InstanceCardDrawer`连续展开/收起，可中途反向；收起后不占高度，使用`inert`、`aria-hidden`、指针隔离与延后隐藏防止幽灵点击和键盘聚焦，减少动效时不保留延迟。操作行左右与底边均留10px，与26px外壳圆角和16px按钮端部半径形成同心轮廓。不靠缩小字号、点击高度或改变卡片材质换取空间。

日志单独滚动，命令输入固定在同一个日志井底部，两者共用终端字体与行高；大量日志不再把输入推到滚动区域外。收起时全卡点击均可展开，包括终端、提示符和命令输入框，输入框同时保留聚焦与草稿；展开后继续点击或编辑输入框不会误收起，功能按钮仍执行各自操作，日志选字与滚动不触发切换。标题可用Enter/Space操作，Escape收起并还原标题焦点。仅为活跃日志区观察尺寸变化，展开/收起时保持原有吸底，已向上阅读时保留阅读位置，不增加轮询或React逐帧状态。运行卡仅取消成功行额外加亮/加粗，提示符也使用400字重，正文与共享终端使用相同颜色令牌，错误色和输入色仍保留。底部按钮不再使用接近纯黑/纯白的文字，危险操作继续复用原语义色，hover恢复更清晰的反馈；不降低整卡opacity。保留隐藏滚动条、命令投递、日志订阅与草稿状态。Enter/Space仍在组件边界隔离，不让外层翻转卡片吞掉按钮键盘操作。

`RunningConsoleCard.css`保留外壳宽柔渐变，不加菜单细框。白天运行壳使用轻微暖调的浅灰 `rgba(238,237,235,0.92)`，内部终端直接复用下节统一材质，不单独覆盖背景或重新定义文字色令牌。仅小幅回暖以缓和发蓝观感，不恢复米黄；日间底部渐变采用中性灰而非偏紫暗部。透明度与渐变强度不变，标题、操作与输入提示保持清晰。关闭操作通过语义类复用 `--destructive`，避免运行时将所有 `text-red-*` 统一降为72%不透明度后覆盖局部可读性设置。暗色外壳配方不变，常态投影与普通卡片弥散按下节调整；无新增滤镜或逐帧逻辑。「减少动态效果」模式仍保留防镜像修正；普通翻转弹簧、拖拽、翻页和归位曲线不变。

## 卡片内重命名

未运行的实例通过三点菜单打开卡片标题处的输入栏，不使用独立弹窗，不恢复双击或失焦保存。运行态不提供重命名入口，保留原顶栏与终端布局。原异步重命名业务、保存锁、错误提示和运行中目录保护保持不变。

`InstanceRenameField`在操作菜单退场后才挂载，输入栏原位显示，不再整行上下移动或缩放。标题与输入栏在同一轮200ms过渡中交接，退出开始时原标题就同步恢复，不等待输入卸载后再出现。退出通过实际CSS过渡的`finished`完成卸载，不靠固定计时器；减少动态效果和入场中断无需额外等待。编辑态不继承标题的放大，避免窄屏输入和保存按钮越界；实例身份消失或变成运行态时直接清理已不可见的编辑状态。

`preview-card-subtitle`与`preview-card-status`由React声明，材质运行时只测量并更新标题抬升距离，不再向React节点补写这些类。否则明暗切换时React会覆盖运行时补上的标题类，标题先落回底部，再在运行时补回类后重新抬起。切换主题须同时检查父标题实际位移和输入节点/草稿，不能只检查输入框的`data-state`没有重播。

`FlipCard`两面的`inert`使用真实布尔值，隐藏面即使有已展开的子抽屉也不能抢占点击或焦点；不改变可见面判断、物理翻转、悬停或拖拽参数。

## 状态选择控件

设置分类、背景模式与主题、新建实例向导、管理分类共用 `ios-choice-track`。轨道和选中底板只保留柔和的深色内凹阴影，不叠加半像素白色下沿高光，避免明暗切换时旧选中项的亮边在溶解中残留。底色、不透明度、圆角、尺寸及原有溶解曲线保持不变；行内取色滑块和白色拨杆不因此重做。

## 终端样式

全局终端、实例管理终端、运行态卡片及启动日志共用 `TerminalWell` 和 `src/styles/terminal.css`。四处白天日志底色统一为 `menu-surface.ts` 的 `rgba(226,225,223,0.84)`，共用原有内凹阴影；不保留运行卡专属背景令牌、旧米黄色回退或调用处的独立配色。圆角统一为常规 20px、紧凑 14px；管理菜单随原有设计帧一起缩放。

白天终端采用同一浅灰日志底与深灰文字，不再保留深色或米黄色日志井。由 `TerminalWell` 根据 `isLight` 统一设置 `data-terminal-tone`，日志、提示符、占位符、错误文字和管理页内部工具共用颜色令牌；提示符与占位符统一沿用原运行卡较清晰的78%/76%墨色，不在组件中单独加深。深色和动态模式维持原配方。运行卡仅按紧凑信息层级调整字号、字重及标题/操作文字，日志底色与正文令牌不分叉，无新增描边。

日志与命令输入统一使用常规系统等宽字体，依次尝试 SFMono-Regular、Consolas、Menlo、Monaco、Liberation Mono，最后使用平台 monospace。中文与全角标点通过仅覆盖 CJK 字符范围的 `Terminal CJK` 本地字体别名，优先 Noto Sans SC、苹方等 UI 黑体，再尝试微软雅黑 UI 与平台 CJK 字体；不用同一个字体列表混排，避免手机缺少桌面等宽字时，CJK 字体同时接管英文并破坏代码列对齐。不再使用 Maple Mono 的装饰性字形。禁用编程连字，不改变命令字符；不新增在线字体请求、CJK 字库或依赖。标题继续使用应用 UI 字体，既有字号、字重、行高、材质和布局保持。原 Maple Mono 资产与许可留存，但终端不再声明或加载它。

## 卡片体积层

停止态与动态模式创建卡片的常态弥散由 `src/styles/card-volume.css` 负责，沿用首次的两层宽径向梯度与软内阴影，位于封面之后、原同级遮罩之前。白色径向高光由深色/动态的7.5%减至4.5%、白天的30%减至16%，白色软内光由12%减至6.5%；暗部与渐变范围不变，只保留隐约体积感，不再靠泛白分离卡片。透明图、普通图片、默认与动态创建卡共用同一套配方，原有阅读渐变保留。静态模式（白天、暗夜及自定义壁纸）的创建实例卡片不挂载弥散层，仅保留原有玻璃材质和拖拽取样。

不保留封面装饰副本、光学柔焦、饱和度增强、透明轮廓投影或后续独立白色弥散试验。原图只有一份，既有透明像素判定与封面设置不变；体积层不使用 filter 或 backdrop-filter，不增加细亮描边。

体积层只读取既有 `--reorder-lift`，抬起时退去、归位时连续恢复；不新增采样、逐帧脚本或拖拽状态，不改 `frozenCoverPlate.ts` 的背景映射。按钮、拨杆与管理菜单不使用这层材质。

## 卡片阴影与拖动边缘

翻转卡片的外投影仅由转子负责；主题运行时的通用卡片阴影不再重复作用于翻转卡片内部。白天创建卡常态投影与所有卡片的抬起投影通过 `--fc-shadow-tone: 0.32` 收淡，保留原有双层柔影，不覆盖用户保存的阴影参数。

普通与运行卡的两层常态柔影单独通过 `--fc-rest-shadow-strength` 增强：深色/动态为1.5，白天为5。白天原有5%阴影系数还会乘以25%/15%，实际只有约1.25%/0.75%；增强后约6.25%/3.75%，仍是低不透明度软影，而非黑色描边。阴影范围、接触层位置和原指针跟随投影保持不变；该令牌不参与创建卡、按压、长按或拖动投影。

拖动投影的镂空轮廓内收2px、圆角相应内收2px，覆盖卡面1px裁切边缘的抗锯齿接缝；卡面裁切与尺寸不变。原卡面及采样底板的内高光使用 `--fc-edge-light` 随既有抬起进度退去、归位恢复，不增加描边、羽化罩层或新的背景采样。

## 白天配色

白天页面保持原来的 `#f0ece8`，页面、透明封面底板及主题过渡色共用 `--app-light-surface-rgb: 240 236 232`，不再给整页加黄或给透明封面单独铺白。运行态外壳采用仅微暖的浅灰，四处终端按上节共用同一日间配色；不再使用 `#f2eee4` 浅黄或较深的 `216/210/200` 暖灰，不把运行卡外壳色扩展到页面或普通卡片。运行卡背面仍透明，菜单外壳材质不改。

弥散仅按上节减弱白色高光；原有阅读渐变和封面图片的亮度、饱和度、模糊参数保持不变。主题运行时通过页面的 `data-theme-tone` 判断明暗，不能依赖具体背景色的 Tailwind 类名，也不通过修改拖拽采样或归位遮罩来解决常态泛白。

白天默认阅读色恢复 `[252, 252, 252]`。仅对曾应用 `20261103-light-warm-v1` 且仍使用 `[252, 249, 241]` 的版本 3 白天草稿做一次默认色回退；其它自定义颜色、字段、时间戳、深色/动态草稿、保存槽、历史及更高版本草稿不改。回退完成后用户重新选择的颜色不再被覆盖。

## 状态切换与取样调度

`useBackgroundMode` 统一管理背景模式、明暗选择、动态暂停与原有持久化键；从动态模式切向已选白天时仍先卸光斑、等待两帧再切换。不再通过 React 添加、再由材质运行时删除根节点的 `theme-smoothing`，避免全树1000ms过渡与已有260ms背景过渡、220ms主题wash竞争。保留控件局部过渡、流光与原有物理动画；主题wash只取消自身持有的动画，材质标记只在值变化时写入。

透明封面与创建实例卡共用 `useFrozenCoverPlate`，统一图片加载、透明像素判定、60ms补采样、窗口尺寸监听与卸载清理。`queueFrozenPlate` 在同一微任务内按底板去重，先集中读取场景、几何与动画相位，再更新各卡片；普通刷新遵守拖动/归位保护。拖拽入口仍可同步调用 `fillFrozenPlate`，它会取消同底板尚未执行的排队请求，不延迟抬起首帧。底层背景选择、坐标映射、28px模糊与图层配方保持原样。

轮播的菜单、重命名、创建入口使用稳定且依赖完整的回调，让原有 `React.memo` 能跳过无关表单或搜索更新。`FlipCard` 的可见面独立记录实际物理朝向，只在跨越正反面边界时更新 React 状态；不能拿上一次完整落稳的逻辑结果判断当前可见面，否则中途切回会残留错误的 `visibility` / `inert`。弹簧参数、逐帧积分、倾斜、按压、翻页与归位曲线不变；长按重排的邻卡让位使用 `cubic-bezier(0.4, 0, 0.2, 1)`，保持380ms并支持中途反向，避免槽位切换时突然弹开。

性能验证必须区分样式计算总耗时、单帧间隔和实际设备体验，不以脚本运行变短推断全部动画达到120Hz。此次保留日志原有50ms批量发布、2000行上限和非活动订阅关闭，没有为追求数字降低模糊、删流光、冻结拖动背景或改视觉配方。
