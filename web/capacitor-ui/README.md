# SillyClient UI

Android、Windows 和 GitHub Pages 共用同一套 React 控制台。本目录是主仓库维护的未适配基线前端源码。

```bash
pnpm install --frozen-lockfile
pnpm run dev
pnpm run typecheck
pnpm run build
```

`pnpm run build` 只生成 `dist/`。Android 使用 Android 仓库的 `scripts/sync-frontend.mjs` 同步，Windows 使用 `Sync-Frontend.ps1`，Pages 使用本仓库 `scripts/sync-pages-app.mjs`，不直接修改生成副本。

平台能力通过 `src/capacitor-plugin.ts` 中的 `TarvenEnv` 契约调用。浏览器预览使用 shim；新增或修改方法时必须同时更新 Kotlin 与 Electron 实现。

## 实例卡片信息层级

版本标记保留第一次梯度弥散时的位置与几何：`rounded-md`、10px。字重减至500，白天使用3.5%黑色衬底与60%墨色字，深色使用7%白色衬底与70%白字，三处保持一致，弱化黑块与粗字的突兀感。不增加可见边线或背景取样，继续用 `formatDisplayVersion` 格式化，不恢复已撤回的 `InstanceVersion` 胶囊组件。

运行态恢复顶部名称与版本同排、底部返回/关闭/更多三个按钮的原布局；保留统一终端和隐藏滚动条。Enter/Space 在组件边界隔离，不让外层翻转卡片吞掉按钮键盘操作，不改变拖拽、翻转或命令协议。

## 终端样式

全局终端、实例管理终端、运行态卡片及启动日志共用 `TerminalWell` 和 `src/styles/terminal.css`。日志底色沿用 `menu-surface.ts` 的主题材质，不在调用处另设透明度或文字配色。圆角统一为常规 20px、紧凑 14px；管理菜单随原有设计帧一起缩放。

日志与命令输入使用本地打包的 Maple Mono 等宽字体，中文保留系统字体回退；禁用编程连字，不改变命令字符。标题继续使用应用 UI 字体。字体来源、校验值及 OFL 许可证保存在 `public/fonts/MapleMono.md` 与 `public/fonts/MapleMono-OFL.txt`。

## 卡片体积层

停止态与动态模式创建卡片的常态弥散由 `src/styles/card-volume.css` 负责，恢复首次的两层宽径向梯度与软内阴影，位于封面之后、原同级遮罩之前。透明图、普通图片、默认与动态创建卡共用同一套配方，不再按封面类型加重颜色；保留原有阅读渐变。静态模式（白天、暗夜及自定义壁纸）的创建实例卡片不挂载弥散层，仅保留原有玻璃材质和拖拽取样。

不保留封面装饰副本、光学柔焦、饱和度增强、透明轮廓投影或后续独立白色弥散试验。原图只有一份，既有透明像素判定与封面设置不变；体积层不使用 filter 或 backdrop-filter，不增加细亮描边。

体积层只读取既有 `--reorder-lift`，抬起时退去、归位时连续恢复；不新增采样、逐帧脚本或拖拽状态，不改 `frozenCoverPlate.ts` 的背景映射。按钮、拨杆与管理菜单不使用这层材质。

## 卡片阴影与拖动边缘

翻转卡片的外投影仅由转子负责；主题运行时的通用卡片阴影不再重复作用于翻转卡片内部。白天创建卡常态投影与所有卡片的抬起投影通过 `--fc-shadow-tone: 0.32` 收淡，保留原有双层柔影，不覆盖用户保存的阴影参数。

拖动投影的镂空轮廓内收2px、圆角相应内收2px，覆盖卡面1px裁切边缘的抗锯齿接缝；卡面裁切与尺寸不变。原卡面及采样底板的内高光使用 `--fc-edge-light` 随既有抬起进度退去、归位恢复，不增加描边、羽化罩层或新的背景采样。

## 白天配色

白天页面、透明封面底板与运行态外壳共用 `--app-light-surface-rgb: 242 238 228`，主题过渡色也读取该变量；不再给透明封面另铺更白的 `#fcfaf4`，运行态外壳保留70%不透明度但不额外叠纯白。运行卡背面仍透明，菜单和深色日志井的材质不改。

首版弥散、原有阅读渐变和封面图片的亮度、饱和度、模糊参数保持不变。主题运行时通过页面的 `data-theme-tone` 判断明暗，不能依赖具体背景色的 Tailwind 类名，也不通过修改拖拽采样或归位遮罩来解决常态泛白。

已有版本 3 草稿仅一次将白天原默认阅读色 `[252, 252, 252]` 更新为 `[252, 249, 241]`；其它自定义颜色、字段、深色/动态草稿、保存槽和历史不改。已经完成迁移后，用户再次选择的中性白也应保留。

## 状态切换与取样调度

`useBackgroundMode` 统一管理背景模式、明暗选择、动态暂停与原有持久化键；从动态模式切向已选白天时仍先卸光斑、等待两帧再切换。不再通过 React 添加、再由材质运行时删除根节点的 `theme-smoothing`，避免全树1000ms过渡与已有260ms背景过渡、220ms主题wash竞争。保留控件局部过渡、流光与原有物理动画；主题wash只取消自身持有的动画，材质标记只在值变化时写入。

透明封面与创建实例卡共用 `useFrozenCoverPlate`，统一图片加载、透明像素判定、60ms补采样、窗口尺寸监听与卸载清理。`queueFrozenPlate` 在同一微任务内按底板去重，先集中读取场景、几何与动画相位，再更新各卡片；普通刷新遵守拖动/归位保护。拖拽入口仍可同步调用 `fillFrozenPlate`，它会取消同底板尚未执行的排队请求，不延迟抬起首帧。底层背景选择、坐标映射、28px模糊与图层配方保持原样。

轮播的菜单、重命名、创建入口使用稳定且依赖完整的回调，让原有 `React.memo` 能跳过无关表单或搜索更新。`FlipCard` 的可见面独立记录实际物理朝向，只在跨越正反面边界时更新 React 状态；不能拿上一次完整落稳的逻辑结果判断当前可见面，否则中途切回会残留错误的 `visibility` / `inert`。弹簧参数、逐帧积分、倾斜、按压、翻页、排序与归位曲线不变。

性能验证必须区分样式计算总耗时、单帧间隔和实际设备体验，不以脚本运行变短推断全部动画达到120Hz。此次保留日志原有50ms批量发布、2000行上限和非活动订阅关闭，没有为追求数字降低模糊、删流光、冻结拖动背景或改视觉配方。
